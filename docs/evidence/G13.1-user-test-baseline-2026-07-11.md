## FDL 4.2 运行时证明

运行时类 `ScheduleParameterProviderImpl` 的任务参数生成路径执行以下操作：

1. 对已结束任务读取 `JobState` 中的 `JOB_RESULT`。
2. 使用 `String.format("%s.%s", JobSnapshot.getName(), "opresult")` 生成参数键。
3. 将结果包装为 `EMBED` 参数。
4. 运行时使用的结果字符串包括 `success` 和 `fail`。

`WorkSnapshotBuilder` 和 `DPFormulaServiceImpl` 同时识别以下表达式形态：

```text
${任务名.opresult}
${工作流名.节点名.opresult}
```

结论：`opresult` 是 FDL 原生调度器注入的运行参数，不需要出现在保存任务的 `globalParams`、`taskParams` 或 `nodeParams` 声明中。

## 保存任务 DTO 证明

本机 `db.script` 中已保存的 `WF_PRIP_Stage` 任务包含：

```text
decision_incoming_on_success=11
decision_incoming_total=11
decision_outgoing_on_success=1
condition_and_entity=1
```

Decision 条件实体包含 11 个 `${<前置任务名>.opresult}`，均与 `success` 比较并使用 `AND`。11 个参数所有者均能在保存任务中找到同名节点。保存任务参数声明为空不构成反证，因为这些值由调度器运行时注入。
