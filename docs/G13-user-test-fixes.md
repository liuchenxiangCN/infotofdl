# G13 用户测试问题复核与纠偏

日期：2026-07-13

当前版本：`0.5.5`

状态：条件分支误报已关闭；SOAP 问题独立待证

## 纠偏结论

此前计划把 `${任务名.opresult}` 当作未经证明的变量并在 `0.5.6` 中替换，这一判断不正确，相关代码改动已经回滚。

FDL 4.2 调度器会在前置任务结束后读取 `JOB_RESULT`，以 `<任务名>.opresult` 为键注入内嵌运行参数，结果值包括 `success` 和 `fail`。因此 `0.5.5` 的条件编译方式符合 FDL 原生机制：

1. 前置任务成功条件为 `${任务名.opresult} = success`。
2. 多个前置任务必须全部成功时，各条件使用 `AND`。
3. “并非全部成功”的反向条件等价为各个 `NOT_BELONGS success` 使用 `OR`。
4. `opresult` 是调度器注入参数，不要求出现在任务的手工参数声明中。

## 当前样例确认

`WF_PRIP_Stage.XML` 的 Decision 保存 DTO 中存在 11 个前置任务结果条件：

- 11 条输入连线均为 `ON_SUCCESS`；
- 11 个 `${前置任务名.opresult}` 均与 `success` 比较；
- 条件实体使用 `AND`；
- 每个条件中的任务名都能在保存任务中找到同名节点；
- 保存任务没有手工声明这些参数，符合运行时注入机制。

因此不得以“参数声明中找不到 opresult”为理由删除或替换该逻辑。

## 回滚与验证

1. 撤销拟议的 `0.5.6` 条件分支代码、测试、版本和部署改动。
2. 本机 FDL 只保留并启用 `0.5.5` 插件，完成 Tomcat 重启。
3. 使用 FDL 4.2 运行时类确认 `JOB_RESULT -> <任务名>.opresult` 的注入路径。
4. 重新构建 `0.5.5` 插件。
5. 通过原生条件 probe、工作流图测试和问题 7/8 回归测试。

## SOAP 后续边界

SOAP 请求问题与条件分支结论分离。没有捕获 method、URL、headers、原始 body、调用次数、HTTP status 和异常类别之前，不修改请求实现，也不宣称 `0.5.6` 已具备发布条件。

如后续继续处理 SOAP，应先建立本地 mock HTTP wire contract，并分别对比原 Java 等价请求、当前生成请求和候选实现。客户真实 endpoint 未验证时，最多只能给离线结论。

## 禁止事项

- 不再把 `${任务名.opresult}` 描述为虚构变量。
- 不把手工参数声明为空当作运行时参数不存在的证据。
- 不因条件分支误报发布 `0.5.6`。
- 不把 SOAP 待证问题与已关闭的条件分支问题合并报告。
- 不伪造客户现场运行结论。
